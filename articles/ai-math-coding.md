You do not need math or coding to start learning AI. You can use AI tools, design AI features and build simple automations with neither. Basic coding helps when you want to build your own AI apps. Deeper math becomes useful when you want to train models or do research.

So the useful question is not "do I need math?" but "what kind of AI work do I want to do?" This article splits AI work into three levels and suggests what each kind of builder could make, alone or on a team.

### What can you do with no code at all?

Quite a lot. Plenty of useful AI work happens in plain language:

- Writing and testing prompts that produce reliable results.
- Designing how an AI feature should behave, including what it should refuse or flag.
- Building workflows with no-code automation tools that connect a model to forms, spreadsheets or email.
- Researching users and deciding which problem is worth solving.
- Checking outputs: are the answers correct, safe and useful?

The skills here are clear thinking, clear writing and care with details. In our view, they are easy to underrate and hard to do well.

Example builds: a tested prompt pack for a specific job, a no-code assistant that sorts incoming requests, or a clickable prototype of an AI feature with sample outputs.

### What can you do with some code?

With basic programming, you can build AI apps on top of existing models. Much of this work is ordinary software development: calling an API, handling data, building an interface and putting it online.

Skills worth having at this level:

- Reading and writing simple code in a common language such as Python or JavaScript.
- Calling a hosted model API and handling its responses.
- Working with files, structured data and simple databases.
- Using version control and a code host such as GitHub to share code with a team.
- Reading code an AI coding assistant writes, and fixing it when it is wrong.

For this kind of work, you can usually get started without advanced math. A rough idea of how models work helps you debug, and you can learn it as you go.

Example builds: a question-answering app over a set of documents, a small agent that calls two or three tools, or a browser extension that summarizes pages.

### When do you need real math?

Math matters most when you work on the models themselves rather than on top of them. For example:

- Training or adapting models and understanding why training behaves as it does.
- Designing new model architectures or methods.
- Research roles.
- Careful statistical evaluation of how well a model performs.

The usual starting points are linear algebra, probability and statistics, and calculus. If this is your goal, our suggestion is to learn them alongside hands-on projects, so the ideas connect to something real.

Example builds: adapting a small open model to a narrow task and comparing it with the original, or building a careful evaluation that shows where a model fails.

### How do the three levels compare?

| Level | What you need | Typical work | Example build |
| --- | --- | --- | --- |
| No code | Clear thinking and writing | Prompts, workflows, design, checking outputs | Prompt pack or no-code assistant |
| Some code | Basic programming | Apps on top of models | Document Q&A app or small agent |
| Real math | Linear algebra, statistics, calculus | Training, research, deep evaluation | Adapted model with a comparison |

### How do non-coders and coders work together on a team?

A mixed team can use each person's strengths. Here is a sample split for a weekend build that you can adapt:

- Non-coder: defines the user and problem, writes and tests prompts, designs the interface flow, collects test cases, and leads the pitch and demo.
- Coder: builds the backend, connects the model and tools, handles data, and puts the app online.
- Math-focused member, if you have one: improves model quality, runs evaluations and explains results with evidence.

Non-coders are not passengers on a team. A clear problem, a tested prompt and a strong demo shape how people understand a project. If you do not code yet, say what you will own when you join a team, and own it fully.

If you plan to enter an event, read its rules before you start. They will tell you who can take part and what kinds of projects it accepts.

### What should you learn first?

A good rule of thumb: learn the next skill your current project needs.

- If you have never used AI tools seriously, start there.
- If you want to build apps, learn basic programming next.
- If a project needs better model quality, start on statistics and evaluation.
- If you want to train models, add linear algebra and calculus.

Whatever level you start at, try to finish one small build before you move to the next skill. A finished build shows you what you actually need to learn next, which is often different from what you expected.
